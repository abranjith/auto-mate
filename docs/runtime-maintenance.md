# Maintaining the Python runtime

The server commits two Python projects under `packages/server/runtime/script-env/` and `packages/server/runtime/verify-env/`. Each has `pyproject.toml`, `uv.lock`, and `.python-version`. The exact direct pins and CPython 3.14.6 interpreter are defined in `packages/server/src/execution/dependency-policy.ts`. On startup or first use, the server copies the manifests into `env/` and `verify-env/` under `AUTOMATE_HOME` (default `~/.automate/`), installs the pinned interpreter through uv if needed, then runs `uv sync --locked`. The script environment receives a digest-checked launcher. A prepared status means the environment synced, the resolved Python and package versions were inspected, and its fingerprint was stored.

To change a pin, edit `dependency-policy.ts`, run `pnpm runtime:lock` at the repository root, and commit both projects' regenerated manifests. Check that every locked package has a wheel for Windows x64, macOS arm64, and Linux x64 before changing the interpreter line. Run `pnpm test`, then `AUTOMATE_LIVE_PYTHON=1 pnpm --filter @automate/server test live-runtime` on each platform. The live suite is configured in `.github/workflows/live-python-runtime.yml` for Windows, macOS, and Linux. A new interpreter, package, uv version, platform, or architecture may change a runtime fingerprint and require a new verification before an approved script runs.

The application never runs `uv lock`, `uv add`, or `uv pip install` on a user's machine. A `RUNTIME_LOCK_MISMATCH` means the committed dependency declaration and lock disagree; it is a build issue for the maintainer. A person can retry a failed environment from Settings or `POST /api/runtime/prepare`, but retrying cannot repair a mismatched build. `GET /api/runtime` shows both environments' status and reason without absolute paths.

`--locked`, `--no-sync`, the exact interpreter pin, and `PYTHONSAFEPATH` prevent dependency drift or accidental launcher substitution. They do not limit generated code's file or network access. macOS and Linux have a hard address-space limit; **No memory limit is enforced on Windows.** See [Python run limits](runtime-limits.md) for each provisional control and [Python Runtime and Script Execution](features/python-runtime-execution.md) for the user flow.
